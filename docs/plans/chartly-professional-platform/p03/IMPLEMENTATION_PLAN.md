# P03 implementation plan — original web journal

2 November 2026. Owner: Codex. State: Done — implementation, integrated regressions and original-screen journeys are verified in the [completion evidence](IMPLEMENTATION_EVIDENCE.md). Root records formal package/master acceptance in the P03 gate; this implementation plan does not change those checkboxes. P00/P01 contracts and the original chart/journal tabs are preserved. P02 account access, origin-scoped aliases, revisions, archive, drafts and workspace recovery remain the persistence boundary.

## Model and ordered work

1. **T01: lifecycle and provenance.** Add a journal action service over the existing principal/origin store. Transactions compare the table revision and retain stable request IDs. Manual create/edit/close/partial-close creates immutable before/after history. Open trades have no fabricated close timestamp; quantities, prices, risk and costs use exact base-10 strings with explicit unknowns. Imported/connector facts are source-owned; user notes/reviews are separate versioned records and survive later source corrections. Current numeric fields remain display compatibility only. Add explicit manual/account book destinations, including an empty account book before an import.
2. **T02/T03: statement import.** Implement one documented normalized CSV schema and reusable column/timezone/unit/currency mapping profiles. Parse quoted/newline CSV safely. Reject malformed numbers, invalid currency/unit, ambiguous/nonexistent local DST times, duplicate IDs and unlinked partial fills. Stage source observations and a preview with rows/errors, per-currency totals, inserts/unchanged/corrections/conflicts. Keys are provider plus canonical account plus external event ID, never a global numeric ID or guessed trade resemblance. Commit accepted corrections atomically; retain each original observation and existing reviews. Preserve explicit position IDs for entry/exit/fee events, realized exits, remaining quantity and separate cashflows. Do not derive contract P&L without explicit economics. Repeat/overlap imports must be idempotent. No provider login or remote execution is involved.
3. **T04: useful review.** In the existing Trades/detail surfaces add unreviewed filtering, setup/strategy/tags/decision notes, explicit reviewed status, optional mindset fields and durable chart/screenshot evidence. Make imported financial fields read-only. Add an attachment action with scoped ownership, safe MIME/byte limits, checksum and P02 asset recovery. Keep book/row identity in links and edits.
4. **T05/T06: accounting and scope.** One shared selector controls profile/book/account, current-time period, IANA timezone, strategy, currency, day/week and archived state. Partial exits contribute their own realized dates and amounts; open position count stays separate from realized-exit sample count. Deposits/withdrawals are cashflows, not wins or journal trade P&L. Show account outcomes and unique decision groups separately only when explicit decision IDs exist. Never sum currencies or invent FX. Keep source decimal strings and use decimal-safe arithmetic before numeric charts. Unknown risk/returns remain unknown. Verify independent fixture totals and denominators.
5. **T07: honest analytics.** Remove generic quality scores/radar and unsupported rankings. Show transparent counts, costs, win/loss/break-even denominators and realized sample sizes. Annualized Sharpe/Sortino require a complete documented cashflow-adjusted expected-date return series; otherwise unavailable. Cumulative journal P&L remains labelled separately from account equity.
6. **T08: period review, drafts, export and recovery.** Add daily/weekly review notes/goals with explicit included-trade IDs and drill-through. Retain incomplete/error drafts on the current principal/origin/book, stable retry bodies after uncertain responses, archive and recovery. Export full source/review/history/event content through an additive P02 registry module; preserve old P02 archives with an explicit empty-module upgrade. Local unsubmitted drafts have an explicit separate export and never silently upload. JSON and CSV exports are real files, with spreadsheet formula protection. Run restart/restore/undo tests and actual original UI journeys on an isolated host.

## Backend boundaries before implementation

`journal_records` is a relational child of the existing workspace, with kind/id primary identity and optional trade/book FKs. It holds current normalized events, immutable source observations/history, reviews, period reviews, mappings, import batches and explicit book links. Source rows are not a second browser authority. Existing trade rows are a validated compatibility projection. Account/source ownership always comes from local account proof; JSON cannot supply its own owner.

All CPU-heavy actions run through P02's bounded first-party worker. New `/api/local/v1/journal` transport retains CSRF, bounded bodies, no-store responses and scoped errors. `POST /actions {originId,expectedRevision,requestId,action,payload}` returns a committed workspace and action detail/result. Actions cover create/update/close/partial-close/correct-realization/review/review-period/archive/restore/save-mapping/create-book. Detail/context reads, staged import preview/re-preview/commit, safe attachment upload and scoped JSON/CSV export use this same service. API requests never execute a broker order.

Canonical trade additions: optional `amounts` string/null object for net/gross P&L, commission/swap/fees, risk, quantity and prices; `realizations` with exact realized quantities/amounts and timestamps; remaining quantity; currency/event type; explicit decision/copy grouping; fact/review revisions and review status. Preserve original numeric fields as compatibility projections; an explicit null canonical value cannot become a fabricated zero.
