## Working behavior

Connections → Kraken public data opens `/historify?source=kraken` with its Connections return context. The existing History & data surface offers **Public market data**: search online spot instruments, choose a native interval, fetch a bounded closed-candle preview, review actual coverage/quality and save through the existing immutable Data Library commit flow. The saved version opens in the existing chart or returns to replay setup. No exchange login, API key, private account/book or order interface is involved.

Server routes are authenticated local-workspace GET `/api/local/v1/datasets/sources/kraken/instruments?q=...&limit=...` and CSRF-protected POST `/api/local/v1/datasets/sources/kraken/preview` with exactly `expectedRevision`, `pair` and `interval`. Expected-principal headers bind source reads, preview and retained review/commit requests to the original owner. Static worker actions execute fixed-origin public reads; no supplied URL/code or secret is accepted. Fetching happens before the existing revision-checked preview transaction.

The server chooses mapping, native symbol, quote currency, raw price basis, base-unit volume, UTC continuous calendar and supported interval from verified response/intent. Decimal source strings are retained exactly. Source observation metadata is bounded and schema checked, survives reopening/repreview/publication and bundle export/owner-confirmed restore, and is displayed as provenance rather than an account capability certificate. Re-preview uses retained bytes rather than another network read. Public reviews do not read, overwrite or delete a user's separate unsaved manual CSV draft; returning to a manual import remounts its retained draft normally.

## Actual public access

The [recorded actual read](evidence/kraken-public-access.json) fetched public XBT/USD minute history at `2026-11-03T15:13:48Z`, staged it and saved an isolated owned version. It saved **720 closed candles**, excluded the separate unfinished final candle and verified count, actual last timestamp and content/source checksums. This touched no user records, private account or credential and made zero order calls. The temporary engine/files were closed and removed after the check; the shared HTTP client was explicitly cleaned up by the standalone verifier.

The provider's documentation describes a 720-entry recent-history limit and always-present unfinished final row. The actual response contained **721 raw rows**. The implementation therefore accepts at most 720 closed rows plus one separately excluded final row, instead of rejecting this measured response or silently truncating it. It does not claim older history is obtainable by paginating `since`. The initial recorded read retained **partial** structural quality. Root's browser review then identified that the named continuous calendar had no declared sessions, incorrectly marking every candle outside trading hours. Kraken now supplies explicit UTC 00:00–24:00 sessions for all seven weekdays. No generic quality rule was disabled. Existing staged or saved evidence is retained; a new fetch uses the corrected calendar. [Official endpoint contract](https://docs.kraken.com/api-reference/market-data/get-ohlc-data).
