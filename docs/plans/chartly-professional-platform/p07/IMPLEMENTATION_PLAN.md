# P07 ordered implementation plan — connector foundation

3 November 2026. Written before P07 implementation. All eight package tasks remain unchecked until their implementation, independent review and required tests pass. Existing chart, journal, Workspace, Connections & Data and profile-management UI remain the base. [Package](../07-connector-framework.md), [master](../MASTER_PLAN.md), [canonical handoffs](../../../../contracts/v1/HANDOFF_SEQUENCES.md).

## Decisions and supported boundary

P07 delivers a reusable, account-scoped, read-only connection framework and its certification harness. P08–P10 own complete provider families, P11 owns execution authority/risk, and P22 owns maintained startup synchronization. A measured public response, a deterministic fixture, a typed account label and a verified authenticated account are different evidence. No readiness level or trading permission is inferred from another.

The user has authorized read-only testing against their already logged-in MetaTrader 5 demo terminal and supplied a private credential screenshot. The elevated discovery found the terminal; the Python integration is not yet installed. Prefer attaching to the selected running terminal without changing its login/settings. Never copy credentials or the screenshot into source, evidence, logs or browser storage; use no trading method. Account identifiers and private activity must be masked/aggregated in portable evidence. A missing SDK, terminal/account mismatch or inaccessible provider is an actionable failed access observation, not successful certification.

The first access spikes cover MT5's actual local demo, Kraken credential-free public reachability, and brokerage access prerequisites using official documentation and a bounded unauthenticated probe. A real provider can be marked read-only verified only for the capabilities actually exercised. Crypto/brokerage authenticated capabilities remain unverified without a permitted account. T01 records both successful and blocked spike outcomes; it does not pretend to certify P08–P10.

Keep declared broker accounts, terminals, copy destinations and source labels separate from observed identity/health. Preserve existing numeric account/book IDs and user review history. Binding to an observed account is explicit, account/environment/currency checked, and conflict-preserving. No connector can arm the existing broker dock, Flow, copying or a bot.

## Ordered work

### 1. P07-T01 — real access spikes and versioned adapter plans

Owner: adapter specialist and root. Inspect official documentation, actual installed/running terminal and compatible SDK. Test bounded read-only MT5 identity, terminal version, symbol economics, timestamped quote/history and account-history availability. Always close the Python IPC attachment; do not close the user's terminal. Record Windows/Python/SDK/terminal build, actual supported environment, observed request/coverage bounds and account/history limitations. Test public crypto reachability without private keys; record brokerage demo/auth prerequisites and unavailable access precisely. Create per-adapter subplans before integration; no blanket broker certification.

### 2. P07-T02 — lifecycle, capability and failure contracts

Owners: adapter specialist, root registry. Add data-only versioned adapter declarations and separate identity/account-read/history/market-data interfaces. There is no executable order interface in the P07 production dispatcher. Normalize failures to bounded safe codes: unavailable, denied, expired/revoked, rate limited with retry time, identity changed, partial coverage and unsupported capability.

Lifecycle is configured/unverified → verifying → observed healthy, stale, degraded, recovering, offline or expired. Configuration never writes observed health. Heartbeat freshness derives from actual observed UTC time and an explicit timeout, with no permanent background thread. Reconnect re-observes the same provider/account/server/environment before any ingestion. Credentials have opaque references, generations and revocation, never returned plaintext. Canonical SourceConnection/CapabilityManifest records pass existing P01 validation; richer runtime state is a separate envelope. Capabilities bind exact adapter version, environment, granted permission and measured evidence; order/cancel/protection remain unavailable.

### 3. P07-T03 — registry and original read-only setup workflow

Owners: root service/API, frontend specialist, storage specialist. Add scoped installed connection records separate from mutable legacy profile tables. Use the existing authenticated local proof, CSRF, strict JSON/query validation, revision/CAS, stable request receipts, bounded worker and private/no-store API conventions.

The original profile Connections page and Settings → Connections & Data gain connection setup/status alongside existing configuration. The wizard selects a provider and read-only intent, verifies observed account/environment/server/currency and capabilities, reviews the destination account/book, then explicitly links it. A previously verified account cannot silently become another terminal login. A duplicate source for the same account reuses the account book; conflicts do not rehome trades. Stale requests/owner switches cannot publish another principal's data. Buttons report actionable next steps and preserve return context. Registry history/report export excludes credentials and full private identity from public certification artifacts.

### 4. P07-T04 — encrypted local vault and redaction

Owner: root. Use a dedicated owner/origin/connection-bound encrypted local vault, with a domain-separated key derived from the deployment's existing protected application key. Authenticate scope/generation in the encrypted payload, fail closed on key loss/rotation/corruption, and expose only opaque references and status. Reuse the established cryptographic library rather than invent encryption. No hosted custody, credential-sharing bridge, plaintext GET/export/browser persistence, or secrets in command arguments/temp worker payloads. Process credential writes directly through the small private authenticated boundary so plaintext is not serialized to worker request files. Handle expiry, replacement and revoke with revision fencing. Restored metadata never restores a usable credential or runtime authority. MT5 current-terminal reads use the existing terminal session; no password is needed merely to attach.

### 5. P07-T05 — bounded history, overlap and atomic journal handoff

Owners: history/storage specialist, root integration. Each connection owns immutable source observations, checksum/revision chains, account-scoped cursor, coverage, conflicts and receipts. Fetch bounded pages outside the write transaction, then recheck identity/configuration/credential generation and revision before committing. Repeated/reordered pages dedupe by native event ID and content; corrections retain earlier observations. Missing pages/partial results never delete cached history or falsely advance complete coverage. Extended outage resumes through bounded overlapping windows; rate limits persist retry guidance without busy loops.

Only adapter-declared confirmed normalized trade facts may project through the existing P03 normalization/ledger helpers inside the same transaction as observations/cursor/receipt. Partial fills, balance transfers and unknown submissions remain distinct observations, not fabricated closed journal trades. MT5 raw deals are retained with honest coverage; broad netting/hedging/funding/accounting certification belongs to P09 and must not be inferred from empty or deposit-only history. Unsupported conversion stays visible and retryable. Existing notes, screenshots, review and archive state survive duplicate/corrected imports. One connected book belongs to one account; manual books stay separate.

Register connector metadata/history/cursors in workspace backup/restore/Undo. Old archives normalize an empty connector module. Cross-owner restore deliberately rebinds local references, preserves immutable observations/history, and resets credentials/health/active linkage pending explicit verification. Test rollback between observation, cursor, projection and receipt writes; archive/disconnect does not purge records.

### 6. P07-T06 — deterministic adapter and controlled failures

Owner: adapter specialist. Implement an explicit synthetic diagnostic adapter and reusable fault scenarios for disconnect/reconnect, stale quote, expired/revoked credential, wrong identity, rate limit/retry-after, duplicates/reordering/corrections, incomplete pages, partial fills and unknown order outcomes. Synthetic identity/evidence must be labelled and can never promote a real provider. Fault injection is data-only and bounded, with no supplied executable code or user-provided URL. Unknown submission tests assert reconciliation state and zero automatic resubmission; P07 cannot dispatch trades.

### 7. P07-T07 — conformance evidence and capability matrix

Owners: adapter specialist, root, independent reviewer. Conformance executes deterministic observed assertions, stores versioned checksums/results and supports explicit repeated evaluation. Matrix cells show declared versus tested scope, environment, sample/coverage, checked-at time, evidence and unsupported reason. Raising readiness requires passing required checks bound to the current adapter/version/environment; callers cannot set a readiness enum or healthy flag. Fake results do not certify MT5/crypto/brokerage. Actual MT5 evidence can support only its exercised read-only capabilities. Test forged/missing/stale evidence, permission mismatch and failed/blocked cases.

### 8. P07-T08 — maintenance, recovery and package acceptance

Owners: root and documentation/review specialist. Deliver per-adapter subplan and certification templates covering owner/version, supported OS/products, native account/symbol/quantity units, protection and history rules, quotas/session limits, precise supported scope, test prerequisites, privacy/redaction, reconnect/recovery and re-certification triggers. Update the local API/guide, in-repository architecture HTML/PNG, CI and forward plan gate without rewriting P00–P06 evidence. Leave all P08–P22 package tasks open.

## Additional user-directed Workspace creation correction

Trading-session tags become optional multi-select/custom labels and never overwrite an explicitly selected timezone. Strategy labels are optional. Profile timezone/default symbol/timeframe are defaults, not a required trading choice. Currency is explicit. Independent run capital belongs to its paper account and must be positive/exact; it is not pooled project equity.

The user explicitly requires owned history before creating a replay project. Setup/review therefore selects an actual private Data Library version and reviews its source/checksum/coverage/native interval/currency before creation. An import handoff preserves the owner-scoped non-secret wizard draft and returns to selection. The created project pins that source; any paper run still requires its own reviewed preparation. No missing source is presented as connected or Ready. Legacy empty projects/archives remain readable. Review states what will be created and preserves progress on errors instead of blindly creating duplicate profiles.

P06 supports fixed reviewed spread/slippage/fees and one-times linear collateral. Show those supported assumptions honestly. Do not invent historical bid/ask spreads from OHLC, or add a leverage selector the engine ignores. Document a separate detailed cost/leverage extension proposal requiring a versioned execution model, valid historical bid/ask or explicitly synthetic time-dependent costs, margin/stop-out rules, gap/stress fixtures and migration before such controls are enabled. This proposal does not certify an unimplemented simulator upgrade.

## Frozen integration envelope and ownership

- Root owns `services/connectors.py`, `services/connector_vault.py`, `blueprints/connectors.py`, app/worker/request-limit wiring and integrated verification. API base `/api/local/v1/connectors`: GET catalog/list/detail/history; POST action `{originId,connectionId?,expectedRevision,requestId,action,payload}` with bounded actions create/probe/link/sync/disconnect/revoke/archive/conformance. No financial dispatch.
- Adapter specialist owns `services/connector_adapters.py`, `services/connector_mt5.py`, `services/connector_conformance.py`, pure fault fixtures/tests and per-adapter access reports. Factory resolves static allowlisted provider IDs, never arbitrary module/path/URL. Protocol `describe()`, `probe(configuration,secret=None)`, `history(configuration,identity,window,cursor=None,secret=None)` returns bounded JSON only; connection identity/configuration come from server state. SDK calls always use selected existing terminal path and explicit timeout, always shutdown in finally, and never call order_send/login/settings mutation. Root coordinates operator/account binding.
- Storage/history specialist owns `database/connectors_db.py`, `services/connector_records.py`, `services/connector_history.py`, installed workspace recovery integration and tests. Interface records `load(connection,origin,id)`, `list(connection,origin)`, `save(connection,origin,id,record)`; pure history merge returns new history + confirmed normalized rows. Root and specialist freeze exact record shape before integration. Routine workspace JSON contains no complete connector ledger or secrets.
- Frontend specialist owns connector client/hook/components, existing Connections & Data/profile integration, Workspace profile-creation improvements and tests. No chart redesign; no credential localStorage/IndexedDB drafts. Read adapter capabilities/status rather than a switch. Root and frontend freeze exact API envelope before service hookup.
