# Chartly dead-end and usability audit

Date: 26 October 2026
Scope: the local Chartly checkout

## Verdict

Top finding: the profile-first promise used to break at the chart. Workspace
sent `profileId` to `/trading`, but the terminal ignored it and gave the user
only a generic Workspace exit. This pass makes the chart show the originating
profile and link back to it. It does **not** yet bind the profile's symbol,
timeframe, chart-data destination, executions, or journal attribution; that
remains the connector/data phase and must not be described as complete.

The application is not full of missing pages. The adversarial audit found no
broken primary, account, Tools, or Workspace link to a missing React route,
and no unregistered Flask blueprint. The real problems were concentrated in:

- a broken no-login API-key state chain;
- reachable empty-href documentation/social links;
- complete automation surfaces that were hard to discover or explain;
- honest local wireframes whose next step was not always visible;
- a small number of unused frontend client methods pointing at routes that do
  not exist.

Nothing material was deleted merely because it has no page. REST, webhook,
SDK, broker, MCP, Flow, Agent, API-key, and `/trading` surfaces were treated as
intentional product/API keepers.

## Fixed in this pass

### 1. Profile-to-chart context

- `frontend/src/pages/workspace/ProfileShell.tsx` now sends `profileId`,
  optional `runId`, `profileName`, and `profileKind`.
- Workspace cards, profile overview, Connections, and Replay pass the actual
  portfolio into that handoff.
- `frontend/src/pages/Trading.tsx` consumes the context without redesigning
  the chart: the existing back link becomes the profile name and returns to
  `/workspace/profiles/:id`. The no-API-key state names the profile and says
  why the key is needed.
- Regression coverage: `frontend/src/pages/workspace/ProfileShell.test.ts`.

### 2. API-key state in no-login/local sessions

- `blueprints/auth.py` now returns `api_key` from `/auth/session-status` on
  the broker-session-expired and authenticated fall-through branches.
- `frontend/src/components/auth/AuthSync.tsx` stores that key even when the
  app user is authenticated but no broker session is active.
- `frontend/src/pages/ApiKey.tsx` syncs a fetched or regenerated key into
  `authStore` immediately and explains the key in one sentence.
- Regression coverage: `test/test_session_status_api_key.py`.

### 3. First-use workflow guidance

- Workspace now has a short **Start here** sequence: pick a channel, work
  inside that profile, review in its journal.
- Workspace now highlights **Build & automate** for Flow, the AI Agent, and
  the API key instead of leaving discovery to the top bar/account menu.
- Connections ends with an explicit **Next step** and chart/overview actions.
- Replay labels unavailable feeds honestly as “No data feed connected yet”;
  future broker/public/import options are disabled rather than selectable.
- Journal’s empty Trades state now has an **Add your first trade** action and
  no longer promises a non-existent file import.

### 4. Agent and Flow prerequisites at the point of use

- `AgentSetupGate` is now a two-step checklist: connect a model, then add the
  Chartly API key. `/agent` and the chart Agent panel stay gated until both
  are ready, matching the backend 409 behavior.
- Flow’s heading and empty state now state the WHEN/THEN job and the
  Trigger → Conditions → Action sequence, including copying a webhook URL
  after creation.

### 5. Automation discoverability

- Tools now starts with an **Automate** group for Flow, AI Agent, API Key,
  Platforms & Alerts, Python Strategies, Strategies, Chartink, Telegram, and
  WhatsApp.
- Each card says “use when…” and names its main prerequisite. This gives
  `/platforms`, `/python`, `/strategy`, `/chartink`, `/telegram`, and
  `/whatsapp` a hub without adding top-nav clutter.

### 6. Dead links and aliases

- Reachable Docs links now go to internal Help & FAQ, except GoCharting,
  which opens its real local setup guide.
- Dead GitHub/Discord/community/roadmap/OpenVarsity affordances were removed
  rather than replaced with invented URLs.
- Error pages now return to Workspace, not a removed Home/Login-first flow.
- `/security`, `/traffic`, and `/latency` redirect to `/logs/security`,
  `/logs/traffic`, and `/logs/latency` instead of loading React NotFound.
- Unused `externalLinks` config and unused auth client methods for
  `/auth/session`, `/auth/brokers`, and `/auth/broker/:broker` were removed.

## Remaining dead ends and risks

### P0 — finish the chart as the profile master

The chart context fix is navigation and orientation only. The connector phase
still has to define and implement canonical Trade Intent versus destination
Execution/Deal records, bind the selected chart-data destination, load the
profile’s symbol/timeframe, reconcile fills, and write the profile journal
without double-counting copied destinations.

### P0 — data and execution connectors

- Free/public crypto, forex, metals and commodities feeds are not built.
- MT5/NinjaTrader/TradeStation discovery cannot be done by the browser alone;
  it needs a local backend/desktop bridge and a real secret boundary.
- Delay, lot-noise and comment variation may violate broker/prop-firm rules.
  The UI must continue to warn and must never promise compliant or
  undetectable copying.

### P1 — auto-logging and replay data

- Journal copy must not claim automatic logging until broker sync and
  reconciliation exist.
- Replay needs a real bar source and deterministic run playback before its
  metrics can be treated as backtest results.
- Profile timezone is stored, but daily grouping and drawdown reset semantics
  need an explicit cross-timezone audit before live risk automation.

### P1 — parked or duplicate legacy surfaces

- `frontend/src/pages/Home.tsx` is not routed. The critic found its parking
  intentional/test-locked, so it was not deleted in this UI pass. Decide its
  fate with the future public-site/landing redesign; until then it is dead
  code, not a user-reachable dead end.
- `/analyzer` and `/logs/sandbox` render the same Analyzer surface. The
  top-bar Analyze switch is gone; keep one canonical route and redirect the
  other in a later compatibility cleanup.
- Dead Jinja GET handlers were identified by the backend-orphan pass, but
  were not removed here because this pass was UI/workflow-first. Remove them
  only with route-level tests proving no template or bookmark depends on
  them. `test_editor_strategy.py` was corrected by the critic as
  test-generated, not a standalone cleanup target.
- The chart still has a minor axe contrast finding around favourite-interval
  controls and an 11px mobile label. It was left alone because the chart UI
  is explicitly preserved; fix only as a surgical accessibility change.

### Backend-only keepers

Do not delete backend routes only because no React page calls them. The audit
classified public REST/RestX APIs, broker plugins, webhooks, MCP/remote
surfaces, Flow ingress/monitor routes, Agent configuration, API-key routes,
and websocket examples/configuration as intentional API or compatibility
surfaces. There were zero unregistered blueprints and zero orphaned broker
plugins in the inspected registration graph.

## Ease-of-use rules from this audit

1. State the prerequisite before the click, at the click: model key, Chartly
   API key, broker connection, data feed, or destination.
2. Every empty state must name the next action and deep-link to it.
3. Every power feature gets one plain “use this when…” sentence where it is
   discovered, not only in documentation.
4. A profile is the unit of work. Cross-profile tools may be highlighted in
   Workspace/Tools, but day-to-day chart, journal, connections and risk stay
   inside the profile.
5. A local-only or future capability must say so in the control itself;
   disabled future options are better than selectable promises.
6. Do not add top-bar items to solve discoverability. Use Workspace guidance
   and the Tools Automate hub first.

## Emotion collection refinement

Mindset/emotion collection is now a per-profile opt-in:

- New profiles default it off; the create wizard explains the choice and the
  review step shows On/Off. Legacy profiles without the preference keep their
  existing mindset history visible.
- Profile Settings has a dedicated switch. Turning it off hides the Journal
  Mind tab, daily prompt, calendar mood, state column, and manual-trade
  emotion fields. Existing entries are retained.
- Even when enabled, each manual trade has a separate unchecked
  “Add mindset check-in” option. If it is not checked, the trade stores no
  state, conviction, emotion scores, or emotional note; Chartly no longer
  fabricates Steady/3-of-5 defaults.
- Daily collection was reduced to state, mood, energy, stress, sleep, and a
  note. Diet, caffeine, and exercise prompts were removed; historical values
  are preserved when editing an existing day.
- `summarizeEmotions` ignores trades without an explicit mindset check-in.

Browser evidence is in `log/deadend-audit/browser-emotion-optin.json`, with
screenshots `chartly-emotion-off-journal.png`,
`chartly-emotion-off-manual-trade.png`, `chartly-emotion-settings-on.png`,
`chartly-emotion-on-mind.png`, and `chartly-emotion-on-trade-form.png`.
The walkthrough proved a disabled GBPUSD trade stored no mindset data, then
enabled tracking in Settings, saved a refined daily check-in, and stored a
second EURUSD trade only after explicitly checking its per-trade opt-in.

## Product-alignment pass: global menu and legacy surfaces

Chartly's product centre is a Trading Profile: chart as master, profile-owned
Connections and Journal, Live channels, Paper/Replay projects, and Combined
Live Analytics. The global account menu therefore keeps only Account,
Developer API key, AI Agent, History & data, capability-gated Leverage, and
Advanced/Admin, each with a one-line purpose.

Decisions from this pass:

- Local use is guest-by-default when loopback no-login is enabled. The SPA now
  receives an explicit `local_guest` session flag and presents this as Local
  mode with optional account security, instead of pretending the seeded local
  user is a normal signed-in account.
- The Chartly API key is a developer credential for scripts, alerts, API
  Playground, and Agent access. It is not a broker password or broker API
  credential, and it no longer appears as a generic Tool.
- Action Center is not an account feature. It is the semi-auto order approval
  queue, so it now lives beside Flow as **Approvals & executions**.
- The global `/dashboard` Broker Account surface is retired from navigation
  and routing. Old `/dashboard` links land on Workspace; broker/prop accounts
  are created and switched inside each profile's Connections.
- Sandbox is a real legacy API/strategy paper-order engine, not a dead page:
  it has `/sandbox/api/configs`, `/sandbox/update`, `/sandbox/reset`, and a
  linked `/sandbox/mypnl`. It overlaps conceptually with Replay/Paper
  profiles and carries Indian-market capital/leverage assumptions. It is
  removed from primary navigation and labelled legacy in the UI. Deleting the
  backend is a separate retirement step because strategy/API sandbox paths
  and tests still depend on it.
- Historify is presented as **History & data**. Its bespoke broker, Live
  Mode, and Analyze controls were removed in favour of the shared account
  controls and a Workspace back link.
- Flow Editor received the same header treatment and now links Workspace and
  Automation approvals instead of the retired Dashboard.
- Telegram and WhatsApp are removed from the Tools registry in this step.
  Their backend/frontend code has **not** yet been deleted; that remains a
  dedicated removal pass with its own route, service, socket, and test audit.
