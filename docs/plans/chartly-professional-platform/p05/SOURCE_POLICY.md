# P05 chart sources and replay availability

3 November 2026. Source implementation record; final integration/browser acceptance belongs to the package gate. Preserve the original Trading terminal, toolbar, drawings, indicators, grid and dock.

## Source identity and capabilities

`frontend/src/lib/trading/chartSource.ts` supplies `DatasetChartSource` and `createDatasetChartSource`. One driver owns one canonical immutable version/checksum and one symbol/venue/native interval. The declared provider, currency/price basis, calendar, UTC opening range, volume availability and structural quality remain attached to it. Driver metadata is detached and frozen. The driver exposes historical reads, exact instrument metadata/search, an indicator snapshot provider and disposal. It exposes no trade feed, order route, live stream, credential or account subscription.

The terminal owner branches before creating legacy broker transports. It applies the private calendar without querying broker session APIs, uses the private horizon, and treats source capability separately from environment labels. An owned profile/run context cannot acquire execution authority by presenting `profileKind=live`, an API key or a historical price. The existing connected feed keeps its existing adapter path; it is not silently substituted when saved data is unavailable.

The private feed reuses P04's per-owner serial/coalesced queue, at most 17 consumers and 50,000 candles per fetch. Native identity and receipt checksum are checked; requested windows are clamped and the upper fetch bound is filtered as exclusive. The resolved source window uses inclusive UTC opening bounds. `horizon` extends the final permitted opening to its native close so the last candle is visible. Unknown volume/open interest remains absent; supplied quantities and real zero observations survive. `openInterestAvailable` and the search row's positive display capability use the server's `openInterestKnownRows` coverage; unknown observations do not claim an intrinsic false asset capability.

## Historical study policy

- Same-chart native studies calculate over the engine's revealed replay prefix. Comparison reads/exports retain the engine's prefix restrictions. Existing replay guards and source-change invalidation remain required.
- Independent native snapshot requests support the exact owned instrument/venue and native interval. Warmup is explicit and bounded to 50,000 observations; earlier bars may be read from the same version before the visible run window. This is calculation warmup, not a change to the visible session window or execution ledger.
- A historical `asOf` contains only observations whose declared close is known at or before the cutoff. Final OHLC values of a forming/future candle are excluded. Seeking backward requests a fresh permitted prefix; future price spikes cannot alter that input.
- Intraday native close uses the declared duration, clipped by a known active session close. With no declared calendar, the native duration is conservative; no market opening/session is invented. An observation outside a declared session has unknown availability and is not returned as confirmed historical knowledge.
- Daily requested snapshots require a declared frozen calendar. Weekday/session windows, dated closures, overnight sessions and IANA DST define the daily close. Missing daily calendar support is an explicit unavailable study state.
- Confirmation is capped by the dataset's publication time. An immutable partial tail does not become complete merely because wall time advances. Historical adjusted-price snapshots are rejected because their metadata does not preserve prices as known before a later adjustment.
- Other intervals, other symbols/venues, synthetic expressions and alternate session/adjustment/currency/unit variants are explicitly unavailable through this driver. It does not fabricate resampled candles, use a newer version, blend providers or consult current broker history to satisfy an old cutoff.
- Existing connected timeframe providers reject historical requests unless a point-in-time snapshot adapter is supplied. That refusal is retained. Native-prefix causality is not certification that imported facts were authentic, uncorrected or externally observable at that historic instant.

`terminalComparisons.ts` accepts an optional WebSocket configuration and an immutable mode. Private comparisons have no socket or polling/bar-close/gap-repair timers; connected comparisons retain their existing behavior. Replay still controls visible readings. A request for another identity fails through the source's capability check instead of drawing silently blended data.

## Search and recovery

`datasetSourceChoices` reads at most 20 pages of 100 owner-bound catalog entries. Principal and catalog revision must remain the same across all pages. Duplicate IDs, invalid continuation and stale/foreign pages reject the whole result; no partial list is accepted. Same-symbol versions/providers remain separate choices. Archived versions remain directly readable for saved references but do not appear as new active choices.

The original `SymbolSearchDialog` retains its chips, rows, ranking, focus and keyboard selection. Optional source identity/capability props restrict local expressions/exchanges and provide source-specific recovery actions. Source version participates in row deduplication. Each query/source/close/unmount invalidates its pending generation and aborts its owned signal; older completions cannot populate new results. Rejected searches stop loading, show a plain-language error and offer retry. The existing legacy search function can consume the optional fourth cancellation argument without changing its first three arguments.

The typed dataset client accepts a changed canonical version ID only when the server returns `resolvedFromVersionId` equal to the exact requested alias. The context resolver must additionally compare the saved run checksum and native instrument/interval. A returned arbitrary replacement ID or unrelated proof remains an error. This completes the frontend half of P04's validated cross-owner restore aliases without rewriting old trade/run records.
