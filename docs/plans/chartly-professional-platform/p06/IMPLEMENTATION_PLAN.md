## Discovery and governing decisions

The original chart engine already supplies causal replay clocks, indicators, drawings, grids and a paused `ReplayGroup.seekTime`. P05 resolves actual owned run/source identity and denies broker execution for profile/private charts. P03 supplies paper-book identity, exact-decimal journal realizations, immutable history, transaction/CAS/receipts and reviewed recovery. The existing live sandbox matches incoming quotes and has account/session/margin assumptions: it is not this historical engine. P06 will add backend authority without enabling its broker bridge or replacing the original chart UI.

Use one native immutable version, one linear instrument and one account currency per run. Preparation requires explicit economics: quantity unit and step, price tick, multiplier, quantity/price scales and account money scale. The user must explicitly review values; decimal display precision is not an execution tick. Currency must match the dataset; no guessed FX conversion. The supported account model is `linear-notional-collateral-v1`: one-times entry notional collateral for long and short positions, settled cash = starting cash + realized gross P&L − charged fees, equity = settled cash + unrealized mark P&L, available = max(0, min(cash,equity) − collateral). Short-sale proceeds are not spendable capital. This is a declared educational linear exposure model, not a claim of cash brokerage or derivative margin parity.

Keep distinct entry positions rather than silently netting/flipping orders. Each entry may be bought or sold short; explicit position-specific reduce-only orders close all or part. No automatic opposite-side flip. Closing is permitted despite negative equity; opening exposure requires adequate collateral and fees. Pending orders do not reserve collateral; eligibility is deterministic FIFO, and insufficient funds at execution rejects the order visibly. No volume-based partial fills or queue simulation is invented from OHLC.

## Frozen matching and accounting policy

- The server alone reads normalized candles and known close/availability times. The browser sends commands/counts, never prices, bars, P&L, ledger or playhead authority. Command IDs and expected session revision are mandatory.
- Orders after an acknowledged full candle are eligible only on the next observed native candle. Market uses its open. A stop-market uses an adverse opening gap or touched stop; a limit uses marketable open or touched limit and never exceeds its limit after spread/slippage. Tick prices and quantity steps are explicit multiples; execution prices round adversely, fees round upward to the declared money scale.
- Costs are fixed spread ticks, slippage ticks, fee basis points and per-fill fee, all explicit in the pinned configuration. No swap/funding/FX or hidden liquidity costs. Entry fees affect cash immediately and appear once as fee realizations; exits carry gross P&L and exit fees. Reports disclose total entry and exit costs without double counting.
- Conservative OHLC brackets choose the protective stop when stop and target are both reachable. A new intrabar entry gets no favourable same-bar target credit without a proven path; a protective stop can still apply. Gap stops fill at worse open. Price improvement for a limit remains bounded by its limit. Every ambiguous execution records its assumption.
- Data gaps use pinned `next-observed` policy: never fabricate candles; record/classify declared closures versus missing/unknown gaps and allow eligible orders on the next observed bar with that disclosure. Unconfirmed/out-of-session or unsupported daily-calendar timing is rejected during preparation. Prices and instrument economics that this linear engine cannot represent are explicitly unsupported.
- Finishing never fabricates a fill at an already-seen close. Cancel remaining pending orders, retain marked open positions and disclose unrealized exposure. A user wanting a realized exit must submit a close while a next eligible event exists. An observation-only finished run is valid and explicitly reports zero fills.

## Ordered implementation and acceptance

### P06-T01 — pure deterministic command, position and accounting core

Owner: engine agent. Add `services/paper_engine.py` and adversarial pure tests. No I/O, wall clock, UUID, broker import, global cache or supplied code. ABI: `normalize_config(config)`, `initial_state(config)`, `apply_command(config,state,command) -> (state,events)`, `advance_bar(config,state,bar) -> (state,events)`, `summary(config,state)` and bounded restored-state validation. Inputs/outputs are JSON with financial decimal strings.

Support market/limit/stop entries, long/short positions, position-specific partial/full closes, pending cancellation and entry brackets. Stable command/order/position/fill/event IDs derive from session sequence and caller command ID. Reject invalid units/ticks/steps, nonfinite/exponent/oversized decimals, wrong side/position, overclose and insufficient collateral. Preserve rounding residues on the final quantity close. Verify independently calculated long/short costs, partial/final exits, fee charging and cash/equity/collateral reconciliation.

### P06-T02 — causal OHLC fidelity, costs and gaps

Owner: engine agent; root owns dataset calendar preparation. Each engine bar contains exact original `time`, OHLC decimal strings, `availableAt` and classified gap metadata. Preparation uses the frozen dataset calendar/native interval and publication horizon; no live history fallback. Pin engine version, policy, economics, native resolution, costs, seed and checksum before execution.

Test same-bar stop/target ambiguity, opening gaps, marketable limits, adversely rounded fractional ticks, short brackets, no favourable intrabar target assumption, missing/unknown data, partial final bars, DST/session closes and next-event order eligibility. A future spike cannot change an earlier order or study. State and ledger must be byte-deterministic for repeated normalized inputs.

### P06-T03 — owned run service and lifecycle

Owner: root. Add `services/paper_sessions.py`, local `/api/local/v1/paper` blueprint and existing bounded worker actions. All routes use existing authenticated local proof, CSRF, strict query/body validation, private/no-store headers and scoped SQLite transactions. Preparation verifies actual profile/run ownership, immutable dataset/checksum/alias, native symbol/interval, UTC window, at least two confirmed candles and explicit economics. A compact server-owned `practiceSessions[].paper` marker exposes revision/status without shipping every ledger to routine workspace views.

Add a dedicated local paper-session record table keyed by principal/origin/run, using the existing engine factory/metadata. Store pinned config/manifest, authoritative state, command receipts, complete ledger and checkpoint separately from chart preferences. Limit runs, commands, events, image-free record bytes and advance batches. Initial prepared state is before the first available candle; commands can only execute on future acknowledged native observations. Start/pause/advance/order/cancel/close/finish/branch are trusted service transitions. Generic table saves cannot edit the server marker, manifest, session financial fields or status. Duplicate matching requests return the same committed response; conflicting requests are rejected. No supplied script is evaluated.

### P06-T04 — paper controls in the original chart

Owner: chart agent. Preserve `Trading.tsx`, ChartPane, original toolbar/drawings/rails/grid/studies and dock. Add a lazy original-rail paper session panel for preparation, explicit assumptions, ticket, pending orders/positions, costs and finish/report actions. Render paper orders/positions/fills in the existing dock presentation or a clearly labelled panel; never show unrelated broker account data as paper results.

Add a paper transport control styled like the original replay bar. Play/step request bounded server advances; only acknowledged `asOf` drives a paused all-pane ReplayGroup. Hide/hold the grid until the acknowledged cutoff is applied. Local free replay/scrub cannot rewind the active paper account. Source/layout/context switches cancel stale responses and stop automatic advance loops; they never send broker commands. Keep `context.executionAllowed=false` and existing broker guards, and add explicit server rejection of historical intent fields at broker order ingress. Test direct command/hotkey/context-menu routes, stale responses and uncertain same-body retries.

### P06-T05 — atomic checkpoint, journal and crash recovery

Owners: root service; journal agent storage/recovery integration. Commit session revision, ledger, orders/positions/cash/playhead, run marker, exactly-once journal projection and request receipt in one transaction. No partial pending-advance publication is visible. A worker timeout after commit can retry the same request; a killed/uncommitted transaction leaves the prior checkpoint intact.

Add an installed `paper-sessions` workspace backup module; old archives without it normalize to an empty module. Backup/preview/restore/Undo preserves every checkpoint/command/event and validates bounded data-only engine state. Restore never starts playback. Owner-confirmed restore deliberately rebinds principal/account/book canonical references; immutable candle references still require verified P04 bundle aliases/checksums before resuming. Old owner originals remain intact. Test restart with pending orders and partial positions, duplicate advances, forced failures at publication boundaries, two-writer CAS, archive/resume and restore/Undo with exact bytes/state hashes.

### P06-T06 — rewind as an explicit independent branch

Owners: root service, chart agent UI. The current account cannot be scrubbed backward while retaining future positions or P&L. “Branch from earlier bar” creates a new owned run with a parent reference, same pinned source/config and a fresh independent starting account at the selected acknowledged historical close. It carries no future orders/positions/P&L; original run, captures and journal remain unchanged. The branch's first visible bar is acknowledged without trading against its already-known open; new commands are eligible at its next event. Show this fresh-account meaning before creating it. Reject a future/invalid cutoff or a branch with no remaining eligible bar. Test independent IDs/books/reports and no future financial state leakage.

### P06-T07 — exactly-once confirmed fills to the paper book

Owner: journal agent pure projection; root transaction integration. Add `services/paper_journal.py` operating only on an in-memory journal state inside the run transaction. One position maps to one simulator-origin journal trade in the run's own paper book. Stable run/position/fill keys dedupe projections. Entry fees are zero-quantity fee realizations; partial/final exits are exact quantity/price/gross/exit-cost realizations. Preserve user notes/review state, chart evidence and archive state across later fills. Financial facts are source-locked; no manual financial edit, broad workspace save or duplicate receipt may fabricate a simulator fill.

Create an empty paper-book binding for a prepared unfilled run. “Finish and review” shows actual coverage, costs, open/unrealized exposure and source assumptions and links to that book and original chart decisions. Test entry/open/partial/final, duplicate projection, reviewed notes/captures, flat/zero-trade finish and byte-safe export/recovery.

### P06-T08 — durable reports and independent comparisons

Owner: journal agent report helpers; chart agent original run-card UI. Add `services/paper_reports.py` producing data-only versioned reports with shared canonical `RunManifest`, `Checkpoint` and `MetricResult` adapters that pass P01 validators. The report includes instrument economics, source/checksum, engine/fill/cost policy, chronological observed coverage, cash/equity/drawdown curve, actual ledger/fills/orders/positions, realized versus unrealized costs/results and explicit unavailable ratios/sample counts.

Persist/report the checkpoint identity and deterministic state hash; retain report JSON export and chart/journal drilldowns. The replay project compares selected independent runs with their own starting cash/currency/coverage; remove the misleading pooled project balance. No aggregate equity curve or mixed-currency sum. P21 automated strategy experiment jobs remain separate and must use an explicitly supported engine adapter. Test canonical adapters, zero/unknown denominators, partial/open exposure, different currencies, branch comparisons and identical report checksums after restart.

## Frozen integration signatures and ownership

- Engine config: `{version:1,instrument:{symbol,exchange,interval,currency,quantityUnit,quantityStep,priceTick,multiplier,quantityScale,priceScale},startingCash,moneyScale,costs:{spreadTicks,slippageTicks,feeBps,feePerFill},policy:{id:'native-ohlc-conservative-v1',gap:'next-observed'},seed:0,startTime}`. Monetary fields are decimal strings; counts/scales are bounded integers. Service supplies `startTime`; no dataset economics are guessed.
- Commands: `{id,type:'order',side:'buy'|'sell',orderType:'market'|'limit'|'stop',quantity,limitPrice?,stopPrice?,stopLoss?,takeProfit?}`; reduce-only orders additionally have `positionId` and `reduceOnly:true`. Convenience close is `{id,type:'close',positionId,quantity}`; cancel is `{id,type:'cancel',orderId}`. Service supplies IDs from the stable request and rejects unknown fields. Engine supplies final field documentation before its first integration check.
- API: GET `/api/local/v1/paper/session?originId=…&runId=…`; POST `/api/local/v1/paper/action` body `{originId,runId,expectedRevision,requestId,action,payload}`. Prepare payload contains reviewed config/economics; server overwrites authoritative identity/window. Actions `prepare,start,pause,advance,order,cancel,close,finish,branch`; advance payload `{count:1..500}`; branch `{atIndex,name}`. GET report/ledger and scoped independent comparison endpoints are read-only. Response `{session,workspace?}`; selected session includes config/manifest/checkpoint/revision/status/cursor/asOf/financial summary/active orders/positions/last bounded fills/report/journal link IDs. Full report export is explicit. Client never posts financial state.
- Root owns new run service/blueprint/worker registration/app wiring, dataset availability preparation, backend/API/resource/integration checks and final plan/gates/browser verification. Engine agent owns pure matching/state validation/tests. Chart agent owns paper client/hook/panel/bar, original Trading/coordinator/dock/run-card wiring and tests. Journal agent owns paper table/storage-module/recovery integration, journal/report helpers/tests and related docs. Only journal agent writes workspace_storage/workspace_recovery; root coordinates necessary server-owned field guards.
