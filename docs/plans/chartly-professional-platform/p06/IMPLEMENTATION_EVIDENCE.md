## Implemented workflow and authority

The original chart, toolbar, drawings, studies, grid, rails and dock remain the presentation base. An owned saved practice run can prepare a separate historical paper account through the Paper session rail. Explicit instrument economics, starting cash, native source/checksum/window, costs, engine version and conservative OHLC policy are pinned before the account becomes ready. The service validates journal precision and supported execution prices during preparation and order acceptance, so an unrepresentable financial fact does not first fail after a fill.

The browser supplies bounded commands and batch counts. The server reads owned immutable candles and derives fills, fees, account state and acknowledged UTC availability. Only an acknowledged snapshot moves the paper chart clock; a held grid cannot reveal later history while that prefix is being applied. Profile labels, quotes, layouts, API keys and chart replay controls do not confer execution authority. Historical intent is rejected at broker ingress, including nested intents and direct order-service calls.

Each entry is a distinct long/short position; reductions name their position. Pending entries do not reserve funds. Matching is next-observed native OHLC with explicit spread/slippage/fees, adverse tick rounding and conservative stop/target ambiguity. Cumulative realized gross preserves currency residues over partial closes. The declared account model is `linear-notional-collateral-v1`, with one-times entry notional collateral and unavailable short-sale proceeds.

One owned SQLite transaction publishes state, checkpoint, run marker, confirmed journal projection and command receipt. Stable retry identities prevent duplicate financial effects. A saved paper record is separate from chart preferences and routine workspace metadata. Full workspace backup/restore/Undo retains it; verified dataset bundle aliases/checksums are still required when restored candle references belong to another owner. Restore does not start playback.

Finishing cancels pending orders and retains actual marked exposure. Branching creates a new run/book and a fresh account at an acknowledged earlier close, keeping the original history intact. Reports contain shared schema-validated manifest/checkpoint/metric adapters and deterministic hashes. Selected run comparison retains independent capital/currency/coverage with no pooled equity or currency conversion. [Paper workflow guide](../../../userguide/35-paper-sessions/README.md), [entry from the original chart](../../../userguide/32-charting-terminal/README.md#historical-paper-sessions).
